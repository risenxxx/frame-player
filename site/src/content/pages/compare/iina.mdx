  - q: Is there an official IINA for Windows?

    a: Yes. Both are built on libmpv, the library form of mpv. Formats, hardware decoding, HDR tone mapping and the picture quality come from mpv in both, so a file that plays in one plays in the other.

IINA is the player a lot of Mac users recommend without thinking twice: a native,
good-looking front end on top of mpv, which is about as good a video engine as
exists. The question people then ask is what to use on Windows, where there is no
IINA. [Frame Player](/) was built to be an answer to that — on the same engine, with
the same attention to how a player feels to use — and it runs on the Mac as well,
so one player can follow you between the two.

## What is the same

**The picture.** Every player in that table hands decoding to mpv, so what a file
looks like — HDR and Dolby Vision tone mapping, hardware decoding, scaling — is
mpv's work in all of them. If IINA plays a file well, Frame Player plays it the
same way, on Windows too.

**Your mpv options.** Frame Player keeps an mpv.conf of its own and applies the
options in it at start — written as `name=value`, the way most mpv.conf files
already are. The settings dialog only ever changes the lines it owns,
so an option you wrote by hand is still there after the next launch.

## Where Frame Player goes further

**Previews that show the frame you land on.** The seekbar thumbnail sharpens to the
exact position once the cursor stops, instead of showing the keyframe before it,
and it shows the chapter as well.

**Subtitles matched to your release.** Searching by the file's own fingerprint
finds subtitles made for exactly that copy, and a subtitle made for a different
frame rate is flagged before you download it — that is the one that
[drifts further out of sync](/guides/subtitles-out-of-sync) the longer you watch.

**Skip intro.** When a file's chapters name an opening, a recap or the credits, a
skip button appears over the picture. It matches the whole chapter title, so a
chapter called "Ending the war" is never mistaken for the end credits.

**Torrents, casting and watching together, built in.** A magnet link plays while
it downloads ([how](/torrent-streaming)), a film goes to a Chromecast or a DLNA
television without being re-encoded ([how](/cast-to-tv)), and a six-character
code keeps friends in other places on the same frame ([how](/watch-together)).
IINA and mpv.net can reach some of this through plugins, scripts or Syncplay; in
Frame Player it is part of the player.

## Where IINA is the better choice

<Note>
  **On an Intel Mac**, use IINA: Frame Player's macOS build is for Apple Silicon.
</Note>

- **It is a native Mac application**, written against Apple's own frameworks, and
  it shows. Frame Player's interface is web technology on top of mpv; it is fast
  and careful, but it is not AppKit.
- **Plugins.** IINA has a JavaScript plugin system, and the online-media and
  subtitle features ship as plugins you can update or replace. Frame Player has
  no plugin system.
- **Picture-in-Picture and music mode.** IINA uses the system's own
  Picture-in-Picture and has a mode for audio files. Frame Player has a mini
  player that stays on top — on macOS even over other apps in full screen — but
  not the system feature.
- **Years of use.** IINA has been around since 2017 and has the long tail of
  fixes that comes with that.

## And mpv.net, or mpv itself

On Windows, **mpv.net** is the other well-known mpv front end, and it stays close
to mpv's own way of working: keyboard first, configured through mpv.conf,
extended with mpv scripts. If that is how you like to use mpv, it is an excellent
choice. **mpv itself** is the engine all of these are built on, with a minimal
interface of its own and everything else done through scripts.

Frame Player takes the other road: the features most people end up adding with
scripts — previews, subtitle search, skipping intros, remembering tracks — are in
the player, with a settings sheet instead of a config file, while your mpv.conf
still applies underneath.
