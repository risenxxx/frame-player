[Plex](https://www.plex.tv/) and [Jellyfin](https://jellyfin.org/) solve a real
problem: a library of films kept in one place — often a NAS — and played on every
screen in the house, and away from it. Both do that well. What they are not is a
video player. They are a server that indexes your folders and a family of client
apps that ask it for streams, and when all you want is to watch a film on the
computer it is on, or put it on the television in the same room, everything in
between is overhead. [Frame Player](/) is the other shape: a player that plays the
file itself, casts it, and streams torrents while they download.

## In a browser, a player is only as good as the browser

The easiest way to watch from Plex or Jellyfin on a computer is the web app, and
there the browser decides what plays. By
[Jellyfin's own codec table](https://jellyfin.org/docs/general/clients/codec-support/),
no browser plays DTS sound, Firefox and Safari do not open MKV at all, and ASS
and PGS subtitles often cannot be shown as they are — so they are burned into
the picture, which the same page calls *"the most intensive method of
transcoding"*. Whatever the browser cannot play, the server converts on the fly:
the fan spins up, seeking waits for the encoder, and styled anime subtitles lose
their styling.

Both projects know this, and both have a desktop client that avoids it — Jellyfin
Desktop and Plex's desktop app play through mpv, the same engine Frame Player is
built on. With those, the picture on the computer is as good as ours. What
remains is the shape:

- **They play the library, not a file.** A film has to be in a folder the server
  watches, and scanned, before it can be played. A file you just downloaded, one
  on a USB stick, or one a friend sent you is opened in Frame Player with a
  double-click — and the folder around it becomes the queue.
- **A server has to be running.** Two programs instead of one, a database, a
  scheduled scan — and seekbar thumbnails that are generated in advance by a
  background task for the whole library. Frame Player makes its previews while
  you watch, for the file you are watching.
- **Casting is the other clients' job.** Jellyfin Desktop has had
  [an open request for Chromecast](https://github.com/jellyfin/jellyfin-desktop/issues/490)
  since 2023; casting from Plex or Jellyfin is usually done from the phone app or
  from the web app in Chrome — the client that transcodes.

## On the television

A server's way to a television is **its own app on the television**: the Plex or
Jellyfin app on a smart TV, a streaming stick or a console, which asks the server
for a stream and gets a transcoded one whenever the file is something that app
cannot play. Casting to a Chromecast works the same way — the device runs the
server's receiver app and the server feeds it, converted when needed. Both can
also act as a DLNA server that the television browses by itself — in Jellyfin
through a plugin since 10.9 — but then you pick the film with the TV's remote,
in the TV's menus, from the library the server has scanned.

Frame Player needs no app on the television and no server behind it:

- **DLNA plays the file on the television's own player** — the one the set uses
  for a USB stick — so a release the set already handles goes over untouched.
  Measured on a 4K LG set: a 6.3 GB HEVC HDR10 MKV with Dolby 5.1 sound, no
  preparation, seeking included.
- **Google Cast gets the file as it is, or repacked — never re-encoded.** When
  only the container is the problem, the file is repacked with the picture copied
  as it is, in about ten seconds for a film, and the copy is kept for next time.
- **Each television says what will happen before you pick it** — plays as it is,
  prepared first, or cannot play and why — and the player window becomes the
  remote: seekbar, keys, chapters, the queue and the audio track.

The details are in [how casting works](/cast-to-tv).

## Torrents, while they download

This is the one thing a media server cannot do by design. Plex and Jellyfin play
files from their library, so a torrent has to be downloaded in full by a separate
client, land in a watched folder and be picked up by a scan before the first
frame. For a 20 GB 4K release that is the whole evening.

In Frame Player a magnet link or a `.torrent` file **starts playing in seconds**.
The pieces under the playhead are fetched first, a seek moves the download to
where you jumped, and the readout shows how far ahead of you the file is on disk
([how it works](/torrent-streaming)). The same stream can go to the television
while it downloads, when the set can play the file as it is. And the built-in
catalog finds the release to begin with — posters, seasons, the releases for each,
with their quality, dubs and seeders.

## Where Plex or Jellyfin is the better choice

<Note>
  **If the films live on a NAS and are watched on several screens**, run a
  server. That is exactly what Plex and Jellyfin are for, and Frame Player is not
  one.
</Note>

- **One library, every screen, several people.** Apps for almost every TV,
  phone, stick and console, with profiles, watched status that follows each
  person, and parental controls.
- **Away from home.** A server can stream to you anywhere — Jellyfin for free
  once remote access is set up, Plex with Plex Pass or a Remote Watch Pass since
  April 2025. Frame Player plays what is on the computer and the network it is
  on.
- **Transcoding for weak devices.** A server can turn a 4K HEVC file into
  something an old phone or a slow connection can take. Frame Player never
  re-encodes a picture, so a device that cannot decode the file cannot play it.
- **Beyond films.** Music, photos, live TV and recording — the server is the
  whole media centre.

The two go together, too: a server on the NAS for the living room and the phones,
and Frame Player on the computer you sit at, for the files that never went into
the library and the torrents you want to watch tonight.
